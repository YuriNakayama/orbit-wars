# 🚀 [LB-958.1] Reinforce 改善案

ノートブックを精読した結果、現在のエージェントは「物理予測 + Safe-Intercept + Mission Scoring + Reserve/Available 防衛バッファ + Crash-Exploit(4P限定)+ Proactive Defense」という非常に強固な構造です。改善余地は「読みの深さ」「対戦相手モデル」「パラメータ最適化」「終盤クロージング」の4軸に集約されます。以下、実装難易度と期待スコアを添えて提案します。

---

## 1. 🎯 相手モデル(Opponent Modeling)の導入 — **最大の伸び代**

現コードは敵の挙動を「到着予定の艦隊」と「駐留艦」でしか捉えておらず、敵の**未来の発射**はモデル化されていません。

**具体案**

- **敵の発射履歴を蓄積し、ターゲット選好を学習**:過去N発射を記録し、「敵の送る先 = 私の弱い惑星 or 中立で ROI 高いもの」という分布を作る。`proactive_defense` の重みを敵の「好物」が自分の惑星の場合だけ強くする。
- **敵の駐留艦増加速度(=production) からワンステップ先読み**:敵惑星 p について ETA-1 ターン時点で「敵が p から発射した場合の最悪シナリオ」を列挙し、**サニタイズされた最悪ケースの `needed`** を採用する。現状は `HORIZON=110` で到着台帳しか見ていないため、「敵がまだ撃っていないが撃つ可能性が高い艦隊」を見逃している。
- **対称性エクスプロイト**:マップは4回対称。序盤 ~40 ターンは**対称位置の敵の動きをミラーリング**して自分のプラン候補を生成すると、短いプレイアウトで敵の最適応手に対するヘッジになる。

期待効果: **+30〜60 点** / 実装工数: 中

---

## 2. 🔬 Safe-Intercept の精度強化

現 `search_safe_intercept` は ETA 候補を 1 ターン刻みで回し、`INTERCEPT_TOLERANCE` で許容。以下が弱点です。

- **他の自艦隊・他の敵艦隊との経路交差を見ていない**(敵が途中で私の軌道上の中立惑星を奪って防壁になるケース)
- **自分の到着ターンに惑星が `LAUNCH_CLEARANCE` ギリギリ重なる**と、クリアランス不足で即滅する可能性
- 射角のグリッドが ETA ベースなので、**「少しだけ遠回りして後ろから当てる」戦略**が出てこない

**具体案**

- ETA の刻みを `0.5` 単位にし、分数ターンの射角補間を許す(惑星位置は線形補間で近似)
- 経路上に自分/敵の既存 fleet 軌跡、他の惑星(彗星含む)のスイープ領域を**時空間 KDTree** で衝突判定
- **迂回オプション**として「一度別方向に撃ってから重力的に直線で回り込む」擬似ラグランジュ点戦略…は不要(引力は無い)だが、**2セグメント経路**(中継惑星経由)を許すと太陽裏への届きが改善する

期待効果: **+20〜40 点** / 実装工数: 中

---

## 3. 🌠 彗星(Comet)戦略の最適化

彗星は 50/150/250/350/450 ターンに出現、一時的な production 源。現コードは `COMET_VALUE_MULT=0.65` と控えめ評価ですが、**彗星の残寿命と ROI を時間割引しきれていない**印象です。

**具体案**

- `comet_remaining_life` を明示的に使い、**NPV(正味現在価値)**で `expected_ships = production × remaining_life - needed` を計算。負になる彗星は捨てる。
- 彗星はスポーン時刻が決定的(50, 150, …)なので、**49/149/249 ターン目の事前配置**を計画:スポーン直後に最短 ETA で到達できる艦隊を予約しておく(特に `DENSE_ROTATING_NEUTRAL_SCORE_MULT=0.86` の状況で価値が高い)
- 敵に渡った彗星に対する **"denial snipe"**:相手が彗星から艦を生産する前に少量 snipe して駐留を減らし、再捕獲コストを下げる

期待効果: **+15〜30 点** / 実装工数: 低〜中

---

## 4. 💥 Crash-Exploit の拡張(現在4P限定)

v6 で追加された 2P への拡張余地が大きい:

- 4P 限定なのは「敵同士の衝突」を狙う設計だが、**2P でも「敵の艦隊経路上に自艦隊を差し込んで相打ちにさせる囮」**は可能
- 敵の艦隊が中立を取りに行く途中に、**わざと小さい fleet を中立に先着**させて敵の combat 計算を狂わせる(最大-2番手ロジックの活用)
- 戦闘で**「attacker1 == attacker2 の tie で全滅」**ルールを逆利用: 敵が N 機で来る所に**ぴったり N 機**当てる「相殺狙撃」。現コードは survivor_ships を最大化する向きだが、**敵 fleet を0にするだけで十分な場面**がある(中立奪取 + 敵戦力削減の二重効果)

期待効果: **+10〜25 点** / 実装工数: 中

## 5. 📈 パラメータのベイズ最適化

CONFIG だけで 60+ 個のハイパーパラメータがあり(`STATIC_NEUTRAL_VALUE_MULT=1.4`, `SNIPE_SCORE_MULT=1.12` 等)、手作業チューニングが限界に達しているはず。

**具体案**

- **Optuna + セルフプレイ**:v2 を固定対戦相手に、v3 パラメータを TPE で最適化。1セット 500 ゲーム ×N 候補で実測勝率を評価関数に
- **2P と 4P でパラメータを分離**(すでに一部分離されているが、`VALUE_MULT` 系は共通の印象)
- **ゲーム局面別(序盤 / 中盤 / 終盤 / 追い上げ / 逃げ切り)に context-aware なパラメータテーブル**を用意
- サブミット予算が限られるので、**局所的に疑わしい係数だけ ±20% を grid で検証**するだけでも効く

期待効果: **+30〜80 点** / 実装工数: 低(仕組み)+ 高(計算)

## 6. 🏁 終盤クロージング(Endgame Solver)

`LATE_REMAINING_TURNS=60` / `VERY_LATE_REMAINING_TURNS=25` で分岐しているが、終盤は局面が小さくなるため**限定的な完全読み**が現実的:

- 残り 30 ターン以下かつ総艦数 < 400 程度なら、**ビームサーチ(幅 8〜16)**で「発射シーケンス → 最終 total_ships」を直接最大化
- 現在は貪欲にミッション選択しているので、**最後の 5〜10 ターンで発射する意味が薄い艦を温存**(発射=自分の total に乗るが、途中撃墜リスクがある)。終盤は **"don't launch if expected survival < 1.0"** ルールを導入

期待効果: **+15〜30 点** / 実装工数: 中

## 7. 🛡️ Defense Buffer の精緻化

`_compute_defense_buffers` で `reserve/available/doomed/threatened` を計算しているが、

- **`proactive_keep` が `PROACTIVE_DEFENSE_HORIZON=12` で頭打ち**:敵の遠距離大艦隊(ETA 20+)を見逃しがち → horizon をターゲット惑星の被攻撃リスクに応じて動的に伸ばす
- **doomed 判定後の "evac"**:`DOOMED_EVAC_TURN_LIMIT=24` 内なら退避するが、退避先が**最良の戦略価値を持つ自惑星か**は評価されていない。退避価値 = (受入惑星の production × 残ターン) - (退避コスト)
- **陽動(feint)**:わざと薄い防衛を見せて敵艦隊を誘引 → 途中で別惑星から迎撃、の2段仕掛け

期待効果: **+10〜20 点** / 実装工数: 中〜高

---

## 8. 🧮 計算効率化(時間予算の活用)

`actTimeout=1 秒 + overage`。現コードは 22 秒で全ゲーム走る = 1 ターン平均 44ms と**大幅に余裕**。計算予算を使って深く読むべき:

- ターン開始時に `remainingOverageTime` を見て、**余裕があるときだけ**次節のビームサーチや Optuna-tuned heavy branch を走らせる
- 軽量なフォールバックプランを常に持ち、重い読みがタイムアウトしたら切り替え

期待効果: 上記施策の実現可能性を拡大 / 実装工数: 低

---

## 9. 🧠 ハイブリッド学習要素(上級者向け)

完全ルール型から一歩踏み出す案:

- **価値関数の学習**:自己対戦のログから局面 → 最終スコアの回帰モデル(GBDT 程度で十分)を学習し、ミッションスコアの `value` 成分に加える
- **方策蒸留**:v2 の行動ログを教師に、軽量 NN で `(obs) → (from_planet, angle, ships)` を学習 → タイムアウト時のバックアップに
- RL 丸ごとは時間対効果が悪いが、**パラメータ空間の一部を勾配法で探索**できる

期待効果: **+20〜50 点(成功時)** / 実装工数: 高

---

## 10. 🔍 細かいバグ/挙動リスクの検査

読んだ範囲で疑わしい点:

- `initial_planets` が彗星更新後にプレイヤー間で差分を生む既知問題(ディスカッション #c-number で指摘)があるので、`predict_planet_position` が誤差を蓄積していないか要検証
- `INTERCEPT_TOLERANCE` が広すぎると "当たるつもりで外す" 射撃を許容しうる → 失敗ケースのリプレイ解析推奨
- `FINISHING_HOSTILE_SEND_BONUS=3` など「送り上乗せ」定数は、tie 全滅ルールと衝突すると**意図と逆の損**を出す可能性

期待効果: バグ修正で **+5〜15 点** / 実装工数: 低
